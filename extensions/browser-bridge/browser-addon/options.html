Pi Light browser bridge

Pair once per browser profile: run /browser-connect in Pi and paste the pairing secret below. After that, while any Pi session runs, the add-on connects on its own to the local Pi Light relay at ws://127.0.0.1:19339, and every running Pi session can use this browser profile at the same time; there is no per-session token. The add-on and the relay each prove the pairing secret to the other without sending it, so a different program holding the port, or another extension, cannot pose as either side. The secret is kept in this profile's extension storage; controlled tabs are kept in extension session storage only so the add-on can resume after the browser stops its idle background worker.

Each Pi session opens its own background tabs (grouped as "pi") and sees only those; they close when that session ends unless it asked to keep them. Click the toolbar button on one of your HTTP(S) tabs to let every running Pi session use it; that tab stays on its origin, and clicking again unbinds it. Pi never closes tabs it did not open. Disable stops connecting and closes the tabs Pi opened without keep.

Control uses the browser debugger, so the browser shows a "debugging this browser" bar while a tab is controlled; cancelling it releases control. Pi can read visible text, the accessibility tree, screenshots and recent console/network entries (no headers or URL queries), send real clicks and keys, and run JavaScript in the page. Pi asks you locally before opening a tab. On tabs Pi opened it then acts without asking; on the tab you bound it asks before every click, fill, key press, navigation, script and console read. Programs running as your own user can read the pairing secret file and are not kept out. Pages can still contain private data and malicious instructions; this is not secret isolation.
